# Contributing

Report documentation or client-example issues with a sanitized input, expected behavior and run ID when relevant. Never share API tokens or unnecessary personal data. Keep changes focused on public integration documentation and examples. Do not submit hosted Actor implementation code.

Before submitting an example change, check its syntax, compatibility with the documented Actor input and output, and behavior when a start response is lost. Starts must never be retried automatically. Use local fixtures for error handling; obtain authorization before starting potentially billed runs.
